# ExcuseOps — Ship Happens: GitHub Actions Beyond CI/CD

ExcuseOps is a demo project for exploring GitHub Actions beyond basic CI/CD,
including staged workflow activation, test and production environments, and
optional agentic workflows.

## Start here

[`DEMO-SCRIPT.md`](DEMO-SCRIPT.md) contains the complete English 45-minute
walkthrough, including setup, exact commands, security boundaries, recovery,
and cost-cleanup guidance.

Use this demo directory as the repository root. Do not publish its parent
conference folder or sibling event materials.

## Prerequisites

- PowerShell 7+
- The stable .NET 10 SDK

## Run locally

From the repository root:

```powershell
dotnet test ExcuseOps.slnx --configuration Release
.\scripts\Publish-Demo.ps1
dotnet run --project .\src\ExcuseOps.Web --urls http://localhost:5180
```

The web application will be available at <http://localhost:5180>.

## Customize the excuse catalog

Edit `src\ExcuseOps.Web\wwwroot\data\excuses.json`, then restart the
application. The file must contain a non-empty JSON array, for example:

```json
[
  {
    "category": "support",
    "text": "The ticket is waiting for another ticket."
  }
]
```

Categories are derived from the file (case-insensitive, distinct, in first-seen
order) and exposed by `GET /api/categories` for the web page's category menu.
The catalog is loaded once at startup through the singleton `IExcuseCatalog`.
Missing or unreadable files, invalid JSON, empty lists, or missing/blank
category or text fields stop startup with an explicit error; there is no
fallback. The Web SDK includes the JSON file in published `wwwroot` content.

Everything in `wwwroot` is public. Never put keys or secrets in the catalog.

## Workflow demos

No active workflows are delivered. Activating them is an intentional local
action:

```powershell
.\scripts\Set-DemoStage.ps1 -Stage 1 -WhatIf
.\scripts\Set-DemoStage.ps1 -Stage 1
```

Stages:

- `0`: remove only the demo-owned active CI/CD file.
- `1`: CI.
- `2`: matrix + TEST.
- `3`: same artifact + production environment approval.

`Stage 0 -IncludeAgentic` also removes only `repo-digest.md` and
`repo-digest.lock.yml` from `.github\workflows`. Unrelated files are never
deleted by the scripts.

## Agentic demo

The agentic source is `agentic\repo-digest.md`. Compile it with the documented
`gh-aw` version:

```powershell
.\scripts\Prepare-AgenticDemo.ps1 -Compile
```

No script dispatches a workflow, commits, pushes, or deploys anything remotely.
The inactive `agentic\compiled` backup was generated by the real compiler.

## Automatic issue assignment to Copilot (optional)

`workflows\IssueToCopilot.yml` is a template. To activate it, copy it to
`.github\workflows\IssueToCopilot.yml` on the default branch.

It runs only when an issue is opened by a human repository owner, an existing
contributor (GitHub `author_association` `CONTRIBUTOR`), or a user with write,
maintain, or admin access. Organization membership alone is not sufficient.

Before enabling it:

1. Enable Copilot coding agent for the repository and token owner.
2. Add the Actions secret `COPILOT_ASSIGNMENT_TOKEN` with a fine-grained user
   PAT granting Metadata read and Actions, Contents, Issues, and Pull requests
   read/write access for this repository. A classic PAT with `repo` scope is
   also supported by GitHub.
3. Ensure the token owner has write access and an eligible Copilot subscription.

`GITHUB_TOKEN` alone cannot start the agent. Existing assignees are preserved.
Assignment starts agent work; it does not automatically merge a PR or guarantee
a fix. Contributor issues can trigger billable agent work, so enable this only
if intended.

## Azure stages and cost

Use one `azd` environment per stage: `excuseops-test` and `excuseops-prod`.
`DEPLOYMENT_STAGE` and the GitHub environment names are `test` and `production`.
Two Linux B1 plans incur ongoing costs; see the cleanup warning in
[`DEMO-SCRIPT.md`](DEMO-SCRIPT.md).

Required reviewers are configured separately in GitHub environment settings.
Free, Pro, and Team plans require a public repository for required-reviewer
approval; check your organization's policy. Never publish demo keys or local
`.azure` state. Client, tenant, and subscription IDs are configuration
variables, not authentication passwords.

## Verification and limitations

Local verification covers 43 .NET tests, the deploy ZIP, an extracted app
HTTP/UI/VIP smoke test, Bicep compilation, workflow `actionlint`, and strict
agentic compilation. No Azure provisioning, deployment, cloud approval, or AI
inference was executed. Actual hosted Linux/Windows runners and Azure/OIDC
require off-stage rehearsal.

Generated `gh-aw` YAML uses new queue/inference fields not recognized by the
installed `actionlint` version; the version-matched strict compiler accepts
them.
